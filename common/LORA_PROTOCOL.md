# LoRa 来源号与递增序号

保留现有文本格式，无新增时间戳：

```text
100,目的号,来源号,序号,命令码[,旋钮]

100,1,0,100,2,1000
```

目的号必须为本机 1；来源号、序号均为 0～65535。旋钮与命令码语义保持。旧遥控器来源号 0 的帧仍可解析。

STM32 为每个来源分别保存最后成功接受的序号，最多四个来源，直到 STM32 重启。表满拒绝新来源，不驱逐已有来源的历史。新序号按 16 位半区间比较：65535→0 是正常回绕，差值恰为 32768 或倒序拒绝。此规则要求两次成功接收之间的推进少于半个序号空间。

相同来源＋序号＋载荷的近期重复包不再执行；若 ACK 已明确启用，事务结束后的重复包可回复原确认结果。相同来源＋序号但载荷不同拒绝。近期缓存淘汰后，来源的序号水位仍保留，旧运动包不能覆盖较新的停止命令。不同来源独立比较，这不是来源认证或多遥控器控制权仲裁。

ACK 保持文本格式，目的与来源引用请求中的来源号：

```text
910,请求来源号,1,请求序号,请求来源号,命令码,累计接受数

```

生产配置仍默认关闭 ACK 发射：遥控器静默/回复窗口和无线模块空口时长尚未核实。测试中的 ACK 时序只用于主机模拟。未启用发送端重发；后续确定单次 ACK 超时、最大次数及停止优先规则后再接入。同一次重发必须保持来源号、序号和载荷，新动作才递增序号。

固定来源号不能识别遥控器重启。发送端后续必须保持重启前的序号连续性，或与接收端约定明确的重新建立连接流程；本版不会因为静默、低序号或运动停机而自动清空水位。用户本轮要求遥控器端暂不修改。

串口继续 USART1 115200-8N1、逐字节接收中断＋512 字节软件环形缓冲。ORE/FE/NE/PE 清错并重新启动接收，失败由原 RadioPoll 后续重试；不终止 TX DMA。硬件错误或环形缓冲溢出会标记字节流中断，丢弃残行到下一个换行，禁止将缺字节前后拼成运动命令。未改成环形 DMA，任务周期和优先级保持。

## 一期目标有效期与安全降级

有效期3000ms是用户确认的联调初值，集中在ControlConfig.h。新的幂等运动命令可续期；正常运行中的STOP1续期保留原水平停止语义。相同序号重发、诊断快照、模式/旋钮辅助更新不延长运动目标，也不能解除全停/上浮。失效后双桨立即中立、舵机保持最后成功写入角度。

发送端必须周期续期且间隔小于有效期并留无线抖动余量。仅按键发包的旧遥控器会在持续动作3秒后进入上浮；本轮未改发送端。不要用新序号不断重放模式循环/俯仰切换事件。通用保活/完整目标续期协议仍需发送端配合，不伪称当前已具备。STOP17、保护退出和重新授权后，本地旧视觉/自动结果被代次屏障拒绝；跨MCU复位的空口旧帧仍需新会话规则。
