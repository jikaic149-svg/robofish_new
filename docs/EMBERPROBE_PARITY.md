# EmberProbe 常规功能接入核对

核对日期：2026-10-16。基线：[上游 README](https://github.com/BakeSheep/EmberProbe-MCU-Flash-Debug#readme)、本机 EmberProbe **0.8.3** 的实际代码和配置清单；工作站桥接扩展 **0.2.1**。探针、目标身份缓存与链路状态现在直接显示在开发页。

本轮按已确认的范围接入常规功能。实验性的外部 GDB、不限速采样、CPU 负载估计、多核共享组不纳入验收。

网页提供操作界面，VS Code 宿主运行原有引擎。文件选择、SVD 来源许可、驱动切换和原生写入授权仍使用原生对话框。网页集中入口并不取消这些对话框。

## 逐项对照

“原控件”表示加载原版 HTML/CSS/JS，并通过消息桥与原引擎交互；“任务映射”表示网页操作调用原生接口。表内所有目标硬件效果均待上板验收。

## 验证证据

- PC 回归：`python -B -X utf8 -m unittest discover -s tests`（在 `esp32s3/AmphiLink_UI`），79 项。
- 原生任务桥：`node tools/emberprobe/bridge/test_bridge.js`。检查 attach 不下载、脚本引用、线程和分页参数、工厂镜像哈希与拒绝授权传播。
- 网页传输：`node tools/emberprobe/bridge/test_webviews.js`。检查双向消息、断线补偿、首次资源注册、CSV 下载及失败清理。
- 浏览器：`tools/emberprobe/verify_native_browser.py`。自建回环服务，加载真实原版控件、检查资源请求、初始化消息及实际 ELF 符号进入变量列表（当前 ELF 静态列表为 123 项）；涉及目标的线程、断点、单步和内存任务使用明确的拦截数据。检查 390px 布局及页面异常；结束后关闭自建服务。
- 安装适配：对真实 0.8.3 bundle 的三个兼容接口做过重复安装与逐字节恢复检查，原版备份和 SHA256 位于 `tools/emberprobe/engine`。

本轮没有连接、暂停、复位、擦除、烧录或写入实物。界面与接口核验不能替代探针、实时采样、断点命中、DMA 时序和真实写入回读的上板验收。

## 安装与恢复

运行 `tools/emberprobe/install.cmd`；已有工作区 SDK 时可运行 `python tools/emberprobe/install.py --bridge-only`。工程专用 OpenOCD 脚本安装到所选工具的 `share/openocd/scripts/interface/robofish` 和 `target/robofish`。Wi-Fi 连接时同步当前工程的探针地址脚本。

兼容接口只增加：导出当前 provider、使用原消息处理器、允许向原图表传入网页容器。恢复原版：`python tools/emberprobe/compatibility.py --restore`，随后重载宿主窗口。恢复前会校验备份和当前文件，已有其他修改时不会覆盖。

网页导入 ELF/SVD/MAP/LD/IOC 单个文件上限 4 MiB；较大的 ELF 可放入工程构建目录或通过原版文件选择入口配置。
